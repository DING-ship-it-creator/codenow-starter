# 小工序设计系统

## 设计取向依据

小工序面向不熟悉产品拆解的运营、设计等用户，核心任务是把日常工作描述逐步整理成可确认、可导出的文档。沿用 PRD 指定的桌面优先编辑画布、浅灰底、暖白内容区、近黑文字和细线边框；让每一步只承担一个主要动作，并用清楚的文字反馈降低需求梳理的不确定感。

### 用户画像适配

| 维度 | 来自 prd.md 的要点 | 对应设计决策 |
| --- | --- | --- |
| 用户熟练度 | 林澄“不熟悉编程，也难以把‘做个小工具省时间’拆成清楚的需求和功能范围” | 使用日常语言标签与示例提示；不用技术术语作为表单标签。 |
| 使用频率 | 场景为周一例会前汇总工作，非持续监控型工具 | 入口直接开始一次梳理；不做复杂常驻导航、历史列表或仪表盘。 |
| 注意力状态 | 用户要补充现状、目标、参与者和例外情况 | 澄清页一次突出一个问题，旁边保留简短需求摘要供纠正。 |
| 任务严肃度 | 产物会交给团队讨论或供 Codex 后续开发 | 用克制的中性色、可读层级和明确确认状态；错误说明具体且可恢复。 |
| 信息密度 | 结果包含较长 PRD 与 MVP 清单，桌面优先 | 工作区采用宽松行距、分节标题和最大行长；摘要与正文分区。 |
| 情绪调性 | 用户希望助手引导梳理、而非要求先掌握产品方法 | 用平实、鼓励但不夸张的提示；空态提供下一步动作。 |
| 核心转化动作 | “预览、修改并确认生成的方案”，随后复制或下载 Markdown | 主动作固定且显眼；确认、复制、下载状态分别反馈。 |

可追溯决策：画像中的“难以把……拆成清楚的需求和功能范围”对应首页日常语言提示与可点击的描述示例，以及澄清页的单题交互。

## UI 技术栈与组件策略

- **样式**：Next.js App Router + Tailwind CSS + CSS variables；在全局样式入口定义语义 token，组件使用 Tailwind utilities。
- **组件**：以 Tailwind 组合为主；如需 Dialog、Dropdown、Select 或 Tabs，采用 shadcn/Radix 风格的基础无障碍组件，避免引入复杂组件系统主导文档画布。
- **图表**：无。PRD 不需要图表。
- **禁止**：独立 CSS 文件堆叠、CSS-in-JS、用 emoji 充当功能图标、同一页面混用多个图标库。

## 图标 Iconography

- **图标库（全站唯一）**：`lucide-react`。
- **安装包名**：`lucide-react`。
- **尺寸 token**：导航 `--icon-nav: 20px`；按钮内 `--icon-inline: 16px`；提示/空态 `--icon-empty: 40px`。
- **线宽 / 风格**：统一使用 1.75px 左右的线框风格；图标与文字基线对齐。
- **无障碍**：纯图标按钮必须带 `aria-label` 或 sr-only 文案；导航项图标搭配文字；键盘焦点清晰可见。
- **动作映射**：新建 `plus`；示例 `lightbulb`；展开 `chevron-down`；继续 `arrow-right`；返回 `arrow-left`；助手提示 `sparkles`；编辑 `pencil`；确认 `check`；复制 `copy`；下载 `download`；清除 `trash-2` 或 `x`。

## 媒体与占位图

- **默认策略**：核心流程不需要照片或头像。局部示意使用 CSS token 渐变、内联 SVG 或纯文本；如未来需要静态占位资源，存放于 `public/placeholders/`。
- **Unsplash API / 远程图源**：不接入。无需摄影内容，避免增加外部依赖。
- **尺寸与 a11y**：有意义的图形提供可读替代文本；纯装饰图形使用 `aria-hidden="true"`。固定容器尺寸，避免布局跳动。
- **按界面**：首页示例用文本卡片；澄清页用“用户/助手”文字标签，不用头像；结果页以文档排版和小标签区分内容类型。

## 数据与演示内容（设计侧约定）

- **数据来源类型**：痛点输入与未生成结果为 `EMPTY`；逐题澄清、PRD 生成使用 `LIVE`（当前用户输入经模型实时处理）。
- **演示策略类型**：输入页/结果未生成态为 `EMPTY_CTA`；模型能力未配置时，澄清与生成显示 `LIVE_UNCONFIGURED`。不提供冒充实时 AI 结果的 fixture。
- **FIXTURE 默认路径**：无；当前 MVP 不使用固定示例答案替代个性化澄清或生成。
- **FIXTURE 是否显示「示例数据」角标**：无 fixture；如果后续经产品确认加入独立静态演示，必须全程标注“示例内容”，且不得使用当前用户输入生成的假反馈。
- **LIVE 未配置态**：说明 AI 服务暂不可用或尚未配置；保留用户已输入内容，提供稍后重试/继续手动编辑的路径，不显示“已分析”或伪造的个性化结果。

## 组件气质与关键界面状态

- **首页 / 痛点录入**：主标题、简短说明、多行输入、可展开的可选背景字段和一个主 CTA。空输入时解释要描述什么；空白或纯空格不可提交。
- **需求澄清**：一次只强调一个问题；需求摘要可见且可纠正。加载时显示明确文案；错误保留输入与答案并提供重试。
- **结果预览**：章节清楚、长文行长可控，每节可编辑。草稿/已确认标识常驻；复制和下载有独立成功/失败反馈。
- **默认 / 空 / 加载 / 成功 / 错误 / 未配置**：状态不能仅靠颜色区分，配合文字、图标语义和操作按钮；聚焦状态与键盘操作可见。

## 响应式或窗口尺寸

- 桌面主工作区 880–960px；澄清页建议主区 680–760px，摘要侧栏约 280px。
- 可用宽度不足以容纳双栏时，摘要折叠或移至正文下方；小屏改为单列，目录折叠。
- 长文本区域随内容增长或内部滚动，不用固定高度裁切；复制/下载等主要操作在窄屏仍可触达。
- 首版验证 1440×900 桌面与 768px、375px 窄视口；避免横向溢出，支持键盘操作与可见焦点。
